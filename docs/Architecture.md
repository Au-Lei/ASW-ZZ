# 港捷物流业务联系单生成系统——架构设计

## 1. 文档约定

- **已决定**：由当前产品范围明确约束，本阶段应遵守。
- **建议**：推荐方案，需经样本或团队评审后采用。
- **待确认**：会影响实现或部署的未决事项。

本文件描述目标架构，不代表当前仓库已经实现相关能力。

## 2. 技术路线

### 已决定

- 第一阶段处理链路为“AI 提取 + 规则标准化 + 人工复核 + Excel 生成”。
- 第一阶段只以船公司入货通知为主要输入；邮件提取和订舱委托书校验留待后续。
- 不明确字段不猜测，允许为空或标记人工确认。
- 数据模型保留字段来源、原始值、标准化值、置信度和人工修改状态。
- 不采用完全无人审核流程。

### 建议

- 使用 Python 构建后端处理核心，将文件解析、OCR、AI、标准化、审核和导出解耦为可测试模块。
- 先以少量脱敏样本验证直线型处理管线；只有在确有分支、重试或恢复需求后，再决定是否引入图编排框架。
- 通过接口适配层隔离 OCR、AI、存储和 Excel 引擎，避免绑定单一供应商。
- Web 框架、数据库、任务队列、AI SDK、OCR 引擎和 Excel 库在样本验证与部署约束明确后再选择，因此当前 `requirements.txt` 不锁定依赖。

### 待确认

- 部署环境、是否允许公网服务、模型与 OCR 的数据合规边界。
- 同步或异步处理、并发量、可接受时延和成本目标。
- 人工复核界面的交付形态及现有系统集成方式。

## 3. 模块划分

建议的最小逻辑模块如下；当前仅建立部分目录占位：

| 模块 | 责任 | 当前状态 |
| --- | --- | --- |
| 上传/入口层 | 文件校验、任务创建、重复提示 | 待实现 |
| 文档解析 | 识别格式并提取文本、页码、坐标和附件元数据 | 待实现 |
| OCR 适配 | 对扫描页/图片识别文字并返回位置与质量信息 | 待选型 |
| AI 提取适配 | 依据版本化 Schema/提示词生成结构化候选字段 | 待选型 |
| 标准化与校验 | 别名映射、日期/编号/箱型处理、冲突检测 | 待实现 |
| 审核服务 | 展示证据、接收人工修改、记录确认与审计 | 待设计 |
| Excel 生成 | 将最终确认值映射到受控模板并校验输出 | 待取得模板 |
| 存储与任务状态 | 保存文件引用、阶段状态、字段结果与审计记录 | 待选型 |
| 编排层 | 串联阶段、错误分流、重试与恢复 | `app/graph.py` 仅占位 |
| 状态模型 | 定义任务、文档和字段状态 | `app/state.py` 仅占位 |

目录意图：

- `app/nodes/`：未来放置阶段性处理节点；节点应聚焦单一责任。
- `app/tools/`：未来放置解析器、OCR、AI、存储、Excel 等外部能力适配。
- `prompts/`：未来保存提示词、Schema 与版本说明，不保存密钥或业务原件。
- `tests/`：未来保存单元、集成、回归和脱敏样本测试。

## 4. 处理链路与状态流转

建议状态流转：

`已上传 → 解析中 → 提取中 → 标准化/校验中 → 待人工复核 → 已确认 → 生成 Excel → 已完成`

任一自动阶段失败时进入“处理失败”，记录可读原因和可重试阶段；出现缺失、低置信度或冲突不一定视为系统失败，而应进入“待人工复核”。

建议链路：

1. 校验文件类型、大小、页数和摘要，建立任务与原文件引用。
2. 优先读取文档内嵌文本；无可用文本的页面再调用 OCR。
3. 组合文本、页码、版面信息和文档元数据，调用 AI 提取字段候选。
4. 验证 AI 响应 Schema，不合规时有限重试；仍失败则转人工处理。
5. 对候选值执行确定性标准化、字典映射和跨字段校验。
6. 展示字段及证据供人工修改、确认，并记录审计信息。
7. 仅使用人工确认后的值填充版本化 Excel 模板。
8. 校验工作簿结构、关键单元格与打印设置，保存输出引用。

## 5. 建议的状态结构

下列是概念结构，不是已实现的数据类：

### 5.1 任务级状态

- `task_id`：内部任务标识。
- `status`：处理阶段。
- `source_documents`：输入文件引用、摘要、媒体类型、页数。
- `field_results`：字段级结果集合。
- `issues`：错误、警告、冲突和待确认项。
- `extractor_version` / `prompt_version` / `ruleset_version`：处理版本。
- `template_version`：Excel 模板版本。
- `created_at` / `updated_at`：任务时间。
- `review`：审核人员、确认时间、整体状态。
- `output_artifacts`：生成文件引用及校验信息。

### 5.2 字段级结果

- `field_name`：稳定的内部字段名。
- `source`：文件、页码、区域或原文片段。
- `raw_value`：AI/OCR 提取的原始值。
- `normalized_value`：规则处理后的建议值。
- `confidence`：来源明确的置信度；不同引擎分值不可直接混用。
- `candidates`：存在歧义时的候选集合及各自证据。
- `validation_status` / `issues`：校验结果及原因。
- `human_status`：未复核、已接受、已修改、明确留空等。
- `final_value`：人工确认后的最终值。
- `modified_by` / `modified_at`：人工操作信息。

建议对箱量及类型同时保存可展示文本与结构化明细，例如数量、尺寸和箱型；最终字段设计需通过多样本确认。

## 6. AI 与 OCR 抽象

### 已决定

- AI/OCR 输出只作为候选，不直接成为最终业务数据。
- 无证据或不确定时输出空值/待确认，不允许提示词诱导猜测。

### 建议

- 定义统一 OCR 接口：输入页面图像，输出文字块、位置、页码、置信度和引擎元数据。
- 定义统一 AI 提取接口：输入文档上下文与版本化 Schema，输出字段候选、证据引用和模型元数据。
- 提示词中明确字段定义、空值策略、候选冲突策略和禁止猜测原则。
- 使用严格 Schema 验证模型输出；记录模型、参数、提示词版本和请求追踪标识。
- 大文件按页或语义片段处理，但合并结果时保留页级证据与冲突。
- 先用真实格式的脱敏样本比较 OCR/模型效果，再决定云服务、本地模型或混合方案。

### 待确认

- 可用服务清单、敏感数据是否可出网、调用成本与响应时间上限。
- 置信度的统一口径，以及人工复核阈值是否按字段分别配置。

## 7. 标准化与校验

### 7.1 别名与标准实体

建议为船公司、箱型、港口、场站建立独立映射表，至少包含：实体类型、标准值、别名、状态、适用范围、来源、版本、维护人与更新时间。未命中的原始值必须保留并提示，不进行模糊替换；模糊匹配只能产生人工候选。

港口是否以 UN/LOCODE 为主键、内部简称如何展示，待业务确认。

### 7.2 确定性规则

- 日期：内部建议使用完整 ISO 日期；缺少年份且无可靠上下文时不补全。
- 编号：按字符串保存，避免数值化丢失前导零；标签和版面证据优先于长度猜测。
- 船名/航次：规范多余空白；大小写和连字符规则待样本确认。
- 箱量及类型：保留原文，并尝试解析为数量、尺寸、箱型；无法解析时转人工确认。
- 别名：只对唯一、启用且版本明确的映射自动标准化。

### 7.3 冲突处理

不同页面、不同提取器或规则结果不一致时，保留全部候选、证据及产生原因。系统可以排序候选，但不得静默覆盖；人工最终值拥有最高优先级并写入审计记录。

## 8. Excel 模板生成

### 已决定

- 输出为可直接编辑和打印的 Excel“港捷物流业务联系单”。
- 只使用人工确认结果生成正式输出。

### 建议

- 使用业务确认的 `.xlsx` 文件作为受控模板，不用代码复刻复杂版式。
- 将内部字段到工作表/单元格的映射配置化，并与模板版本绑定。
- 生成时复制模板，写入值而不破坏公式、合并单元格、样式、打印区域与页眉页脚。
- 生成后校验文件可打开、模板版本正确、关键字段落位且打印设置存在。
- 文件名进行安全处理，并避免覆盖已有输出；保存输出摘要用于追踪。

### 待确认

- 正式模板、字段单元格映射、目标 Excel 版本、打印机/纸型及文件命名规则。
- 揽货人和客服为空时的展示方式。

## 9. 存储建议

建议逻辑上区分：

- 原始文件与生成文件：对象/文件存储，数据库仅保存受控引用和摘要。
- 结构化任务、字段结果、映射表和审计：关系型存储更适合查询和一致性。
- 提示词、规则和模板：版本化管理；业务模板是否进入代码仓库需结合敏感性与发布方式决定。

本地开发可采用轻量方案，但不得将开发便利直接视为生产选型。文件保留期限、删除策略、备份和灾备目标待确认。

## 10. 安全与合规

- 密钥只从受控环境变量或密钥管理服务读取；`.env` 不提交，`.env.example` 只列变量名。
- 上传文件需校验扩展名与实际媒体类型，限制大小/页数，并使用随机内部文件名防止路径注入。
- 对文档解析器进行隔离与超时限制；宏、外部链接和嵌入对象默认不执行。
- 文件访问、审核、下载和映射维护应鉴权并遵循最小权限。
- 日志避免记录完整业务正文、密钥和不必要的个人信息。
- 第三方 OCR/AI 的数据用途、保留策略、地域和合规条款必须在接入前确认。
- 生产数据不得直接进入测试集；测试样本应脱敏并经授权。

## 11. 日志与可观测性

建议记录任务 ID、阶段、耗时、结果状态、错误码、服务/模型版本、提示词/规则/模板版本和重试次数。字段值和原始正文默认不进入普通日志。指标可包括处理成功率、各阶段时延、OCR 使用率、字段缺失率、人工修改率、未映射别名数和 Excel 生成失败率。

日志保留期限、告警阈值和运维责任人待确认。

## 12. 测试策略

- **单元测试**：日期、编号、箱型解析、别名映射、冲突规则和字段状态转换。
- **契约测试**：OCR/AI 适配器输入输出 Schema、超时与错误映射。
- **集成测试**：解析到待复核、复核到 Excel 的关键链路。
- **模板回归测试**：关键单元格、样式/合并区域、打印区域和模板版本。
- **样本回归测试**：按船公司和文件类型维护脱敏黄金样本，区分原始提取与最终标准值。
- **安全测试**：异常文件名、伪造类型、超大文件、损坏/加密文档、恶意文档与日志泄露。
- **人工验收**：业务人员逐字段对照原件，并验证 Excel 编辑与打印效果。

首个标准样例应成为回归用例，但需要原始脱敏文件才能验证解析与 OCR，而不能仅根据期望值构造输入。

## 13. 后续扩展

- 订舱委托书：复用文档解析和字段模型，新增“订舱要求”来源及跨文档差异规则；差异仍由人工确认。
- 往来邮件：增加邮件线程、正文和附件适配，提取揽货人、客服并保留邮件证据。
- 多船公司：通过模板/提示词配置、别名库与黄金样本扩展，避免在核心流程堆叠特例。
- 系统集成：在数据契约稳定后，再考虑与现有业务系统、身份系统或档案系统对接。

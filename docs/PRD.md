# 港捷物流业务联系单生成系统——产品需求文档

## 1. 背景

国际海运货运代理业务中，操作人员需要从船公司入货通知中读取订舱与进场信息，并整理为可编辑、可打印的 Excel“港捷物流业务联系单”。原始文件可能是 PDF、图片或文档，格式和字段写法不统一，人工录入耗时且容易遗漏。

后续还会引入订舱委托书和往来邮件：委托书主要用于检查船公司放出的入货通知是否符合订舱要求；邮件用于识别揽货人、客服等信息。本阶段不处理这两类来源。

## 2. 产品目标

- 建立“AI 提取 + 规则标准化 + 人工复核 + Excel 生成”的可审核流程。
- 从入货通知提取第一阶段核心字段，并保留原始证据和处理状态。
- 对船公司、箱型、港口、场站等名称进行可维护的别名映射与标准化。
- 对不清楚、缺失或冲突的信息明确提示人工确认，绝不猜测补全。
- 生成可直接编辑和打印的 Excel 业务联系单。

## 3. 用户与角色

- **操作人员**：上传文件，核对、修改提取结果，确认并生成 Excel。
- **业务复核人员**：检查关键字段、冲突项和最终业务联系单。
- **系统管理员/维护人员**：维护别名映射、模板版本、权限及服务配置。

角色是否需要严格分权、是否由同一人员兼任，待确认。

## 4. 第一阶段流程

1. 操作人员上传一份船公司入货通知。
2. 系统识别文件类型，提取文字；扫描件或图片进入 OCR。
3. AI 按既定字段结构提取候选值，并关联来源位置或原文片段。
4. 规则层进行格式转换、别名映射、字段校验和冲突标记。
5. 人工复核页面同时展示原文件、原始值、标准化值、置信度和提示。
6. 操作人员修改或确认字段，系统记录人工修改状态。
7. 经确认后，系统使用受控模板生成 Excel 业务联系单。

未经人工确认，不将结果视为最终业务数据。

## 5. MVP 范围

### 5.1 包含

- 上传并处理常见 PDF、图片及文档格式；具体格式清单待样本验证。
- 对入货通知进行文本提取、OCR 或 AI 结构化提取。
- 提取本文件第 8 节列出的核心字段。
- 维护并应用船公司、箱型、港口、场站的别名映射。
- 展示字段来源、原始值、标准化值、置信度及人工修改状态。
- 对缺失、低置信度、格式异常和冲突字段进行提示。
- 人工复核、修改与确认。
- 通过受控模板生成可编辑、可打印的 Excel 文件。
- 保存必要的处理状态和审计信息；保留期限待确认。

### 5.2 非目标

- 完全无人审核或自动对外发送业务文件。
- 本阶段解析往来邮件，或自动识别揽货人、客服。
- 本阶段解析订舱委托书并与入货通知自动比对。
- 直接替代现有订舱、财务或客户管理系统。
- 自动判断含义不明确的字段或凭经验补值。
- 在样本和模板未确认前支持所有船公司、所有文件格式。

## 6. 输入与输出

### 6.1 输入

- 第一阶段：船公司入货通知，来源格式可能为文本型 PDF、扫描 PDF、图片或办公文档。
- 后续：订舱委托书、往来邮件及其附件。

文件大小、页数、格式、加密文件和批量上传限制待确认。

### 6.2 输出

- 经人工确认的结构化业务字段。
- 字段级来源、原始值、标准化值、置信度与人工修改记录。
- 按“港捷物流业务联系单”模板生成的 `.xlsx` 文件，可编辑、可打印。
- 对无法确认、缺失或冲突字段的提示信息。

## 7. 首个标准样例

首个样例用于建立验收基线，不代表所有船公司格式：

| 字段 | 期望标准化值 |
| --- | --- |
| 承运公司 | 马士基 |
| 提单号/Booking No. | 276458899 |
| 合约号 | 299253769 |
| 船名 | MAERSK BERMUDA |
| 航次 | 638S |
| 船期/ETD | 2026-09-30（展示格式待确认） |
| 箱量及类型 | 1X20GP |
| 场站 | 青岛港联海 |
| 起运港 | QD |
| 目的港 | Manila |

“9.30”转换为 `2026-09-30` 需要可靠的年份上下文；若文件或业务上下文不能确定年份，必须保留原值并要求人工确认。

## 8. 核心字段

| 字段 | 第一阶段处理要求 | 备注 |
| --- | --- | --- |
| 承运公司 | 提取并做别名标准化 | 保留原始写法 |
| 揽货人 | 字段预留，允许为空 | 后续从邮件提取 |
| 客服 | 字段预留，允许为空 | 后续从邮件提取 |
| 提单号/Booking No. | 提取；按样本验证格式 | 不因相似编号自行推断 |
| 合约号 | 提取；保留前导零和原始格式 | 与提单号冲突时提示 |
| 船名 | 提取并规范空白、大小写策略 | 具体标准待确认 |
| 航次 | 提取；保留字母与方向标识 | 不拆除有意义后缀 |
| 船期/ETD | 标准化为完整日期 | 年份不明时不得猜测 |
| 箱量及类型 | 解析数量与箱型，同时支持展示值 | 如 `1X20GP` |
| 场站 | 提取并做别名标准化 | 映射表需可维护 |
| 目的港 | 提取并做港口别名标准化 | 是否使用 UN/LOCODE 待确认 |
| 起运港 | 提取并做港口别名标准化 | `QD` 的标准展示规则待确认 |

每个字段至少应预留：来源文件、来源页码/区域或原文片段、原始值、标准化值、置信度、校验提示、人工修改状态、人工确认值及修改时间/人员。

## 9. 人工复核要求

- 原文件与结构化字段应便于对照查看。
- 低置信度、缺失、冲突和规则不通过的字段应明显标记。
- 人工可保留标准化值、改为其他值或明确留空。
- 应区分“AI 原始提取”“规则标准化”“人工修改”和“最终确认”。
- 已修改字段应记录修改前后值、人员与时间；具体审计粒度待确认。
- 生成 Excel 前应有明确确认动作，并再次提示未解决项。

## 10. 异常与冲突规则

- **无法读取**：文件损坏、加密或不受支持时停止处理并给出原因，不生成臆测结果。
- **字段缺失**：保留为空并标记“待人工确认”，不得根据其他单据常识补值。
- **多候选值**：保留候选及证据，标记冲突，由人工选择。
- **日期不完整**：仅有月日且年份无法从可靠上下文确定时，不补年份。
- **编号混淆**：提单号、Booking No.、合约号出现多个候选时，按标签和位置提供候选，不凭长度强行归类。
- **标准化失败**：保留原始值，标记未映射；不得静默替换。
- **别名冲突**：同一别名映射到多个标准实体时暂停自动标准化并要求维护人员处理。
- **重复文件**：建议基于文件摘要提示重复；是否禁止重复处理待确认。
- **AI 与规则不一致**：同时保留结果及原因，以人工确认结果为准。

## 11. 非功能需求

- **准确性**：关键字段必须可追溯到原始证据；字段级准确率目标需通过样本集确定。
- **可审计性**：记录提取、标准化、人工修改和输出模板版本。
- **安全性**：真实密钥不进入仓库；文件、日志和模型请求按业务敏感数据处理。
- **隐私与合规**：第三方 OCR/AI 是否允许接收业务文件需经确认；必要时支持脱敏或本地方案。
- **稳定性**：单个文件失败不得影响其他任务；失败应可定位和重试。
- **可维护性**：提取提示词、别名映射、规则和 Excel 模板应版本化。
- **性能**：单文件处理时延、并发量和文件保留期限待业务基线确认。
- **兼容性**：生成文件应在目标 Excel 版本中可编辑并保持打印布局；目标版本待确认。

## 12. MVP 验收标准

- 使用首个标准样例时，系统能够呈现第 7 节中的期望字段；不确定的年份仅在存在可靠上下文时标准化。
- 每个提取字段可查看原始值、标准化值、来源证据、置信度和人工状态。
- 未识别或不明确字段为空或标记待确认，没有猜测值。
- 船公司、箱型、港口、场站的别名映射可维护且变更可追踪。
- 操作人员可修改、确认字段，并看到所有未解决的异常或冲突。
- 仅在人工确认后生成 `.xlsx`，文件可编辑，关键字段正确写入并满足经确认的打印模板。
- 解析、标准化、Excel 映射及异常分支具有自动化测试；脱敏样本通过验收。
- 仓库、日志、测试数据和输出文件中不含真实密钥。

## 13. 待确认事项

- “港捷物流业务联系单”正式 Excel 模板、单元格映射、打印区域及样式要求。
- 第一批真实且可脱敏的入货通知样本及船公司覆盖范围。
- “提单号”与 “Booking No.” 是否为同一业务字段或需要分别保存。
- 日期缺少年份时可采用哪些可靠上下文，以及界面展示格式。
- 港口标准编码是否采用 UN/LOCODE；`QD` 等内部简称如何展示和存储。
- 船名大小写、箱型表达、场站正式名称等标准字典来源和维护责任人。
- 允许使用的 OCR/AI 服务、数据驻留与合规限制、调用成本上限。
- 部署方式、用户规模、并发量、权限模型、文件和审计记录保留期限。
- 人工复核是否需要双人复核、退回、重新生成和版本留存。
- 支持的文件格式、大小、页数、加密文档及批量上传边界。
